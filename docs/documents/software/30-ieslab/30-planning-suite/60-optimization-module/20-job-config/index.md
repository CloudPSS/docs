## 功能定义

通过设置规划类型、场景缩减方式、求解模式、惩罚参数、系统级约束（预设模板或自定义 DSL）以及项目生命周期、投资组成、资金来源等财务参数，控制优化模型的构建与求解，并在优化得到的方案配置及运行数据基础上，对项目进行全生命周期的财务评价。

## 一、计算方案参数详解

计算方案参数分为**项目设置**、**优化设置**、**财务参数**三组。下表逐一说明每个参数的作用、默认值与设置建议。财务参数（投资组成、资金来源、资产形式、生产成本、流动资金及财务费用、税率及附加）与各财务报表的计算关系详见本文档[第三部分](#三报表计算原理)、[第四部分](#四财务参数说明)。

### 1.1 项目设置参数

| 参数                       | 默认值         | 作用说明                                                                                                   | 设置建议                                                         |
| :------------------------- | :------------- | :--------------------------------------------------------------------------------------------------------- | :--------------------------------------------------------------- |
| **规划类型**         | 典型年规划优化 | 选择规划优化问题的类型                                                                                     | 一般项目保持默认；绿电直连项目选择对应类型                       |
| **规划时段**         | 编辑数据       | 参与优化的时间范围                                                                                         | 一般取全年；与"场景缩减类型"共同决定求解规模                     |
| **场景缩减类型**     | 8760h          | 典型场景生成方式（见[基本原理 · 典型场景生成](../10-fundamentals/index.md#6-典型场景生成与-gmm-聚类算法)） | 初期规划用月度平均；方案深化用全周期聚类；精细化运行优化用 8760h |
| **场景是否可视化**   | 否             | 是否在结果中展示典型日聚类可视化                                                                           | 需要检查聚类效果时开启                                           |
| **是否生成项目报告** | 否             | 优化完成后自动生成 Word 项目报告                                                                           | 对外交付时开启；调试阶段建议关闭以加速                           |
| **是否财务后评估**   | 是             | 优化完成后执行财务后评估                                                                                   | 需要投资决策依据时开启                                           |

### 1.2 优化设置参数

| 参数                       | 默认值       | 作用说明                                                                                         | 设置建议                                                  |
| :------------------------- | :----------- | :----------------------------------------------------------------------------------------------- | :-------------------------------------------------------- |
| **电不平衡惩罚**     | 10000 元/kW  | 电力不平衡时的惩罚成本，同时作用于**缺电**与**富余电弃电**，引导优化优先保障供需平衡 | 应显著高于购电电价；缺供代价越高的项目（如 AIDC）设置越高 |
| **新能源弃电惩罚**   | 0.2 元/kWh   | 弃风弃光时的惩罚成本                                                                             | 可设为略低于当地燃煤基准价                                |
| **最低绿电自消纳率** | 60 %         | 新能源自消纳率下限                                                                               | 绿电直连项目按合规要求设置（如 60%）                      |
| **调度周期**         | 项目周期     | 运行优化的调度时间周期，首末 SOC 相等                                                            | 一般保持"项目周期"                                        |
| **是否优化启停**     | 否           | 启用机组组合（UC）启停优化                                                                       | 含电解槽等且关注运行细节时开启；会显著增加求解时间        |
| **启停自定义约束**   | 选用模板约束 | 支持模板或自定义                                                                                 | 自定义约束较复杂，建议先选用内置模板约束，并学习 DSL 语法 |
| **自定义约束**       | 编辑数据     | 系统级自定义约束列表：预设模板或 DSL 表达式（见[第二部分](#二系统约束与自定义-dsl)）              | 绿电直连合规指标在此配置                                  |
| **优化算法**         | 常规算法     | 求解模式与求解器算法选择                                                                         | 一般保持默认；大规模全年优化可选两阶段并行                |

**惩罚参数协同理解**：电不平衡惩罚、弃电惩罚、软约束惩罚共同构成优化的"价格信号体系"——它们之间的**相对大小**决定了优化在面对"缺供 / 弃电 / 越限 / 多买设备"时的取舍。调整其中一个时，请同步审视其他两个，保持量级关系合理：**电不平衡惩罚 > 软约束惩罚 > 弃电惩罚（相对购电价）**。

## 二、系统约束与自定义 DSL

系统约束是**跨设备**的系统级指标约束（区别于单设备物理约束），如"新能源发电量的 60% 必须自用"、"储能总装机不超过 10 MW"。平台提供两种配置方式：**预设约束模板**（简单）与**自定义 DSL 语法**（灵活）。

### 2.1 预设约束模板

常用合规与规模约束已固化为模板，**选择模板类型 + 填写上下限**即可，无需编写表达式：

| 模板类型                    | 名称           | 方向 | 建议取值示例 | 说明                                                                                 |
| :-------------------------- | :------------- | :--- | :----------- | :----------------------------------------------------------------------------------- |
| `selfuse_ratio`           | 新能源占用电比 | 下限 | 30（%）      | 新能源被本系统用电负荷消纳的比例，**分母为总用电负荷**；绿电直连"绿电占比"指标 |
| `generationselfuse_ratio` | 新能源自消纳率 | 下限 | 60（%）      | 新能源发电中被自用消纳的比例，**分母为新能源总发电量**                         |
| `curtailment_ratio`       | 新能源弃电率   | 上限 | 5（%）       | 新能源弃电量占理论发电量的比例上限                                                   |
| `total_battery`           | 储能总装机     | 上限 | 10000（kW）  | 全部储能设备装机之和的上限（硬约束）                                                 |
| `total_renewable`         | 新能源总装机   | 下限 | 50000（kW）  | 光伏+风机装机之和的下限（硬约束）                                                    |

**占用电比 vs 自消纳率的区别**（容易混淆，务必区分）：

| 指标     | 计算公式                                  | 含义                                           |
| :------- | :---------------------------------------- | :--------------------------------------------- |
| 占用电比 | 自用新能源电量 ÷**总用电负荷**     | "我的用电里有多大比例来自绿电"——绿电占比口径 |
| 自消纳率 | 自用新能源电量 ÷**新能源总发电量** | "发出来的绿电有多大比例被自己用掉"——消纳口径 |

另有 **2 项算法内置约束**（无需配置，自动生效）：

| 内置约束         | 来源         | 说明                                         |
| :--------------- | :----------- | :------------------------------------------- |
| 最大上网率 | 外部电源属性 | 上网比例上限，在**外部电源组件**中设置 |
| 储能保供         | 电池属性     | 保供小时数 > 0 时自动启用                    |

> **启用判定**：下限 ≤ 0 视为未配置、上限 ≥ 100% 视为不限——不生效的约束自动跳过，不会报错。

### 2.2 自定义 DSL 语法

当预设模板无法覆盖工程约束时，可用自定义 DSL（领域专用语言）直接书写约束表达式。您只需写"约束的数学式 + 上下限"，内核自动编译为优化模型约束参与求解。

#### 2.2.1 快速示例

```
光伏总装机不超过 20 MW：
    sum(capacity * unit) @ 光伏    上限: 20000

风电弃电量不超过 1000 kWh（单时段）：
    sum(electric_curtailment) @ 风电    上限: 1000
```

写法要点：**约束体表达式 + 上限/下限 + 是否软约束**。

#### 2.2.2 语法元素

| 元素           | 写法              | 说明                                             | 示例                             |
| :------------- | :---------------- | :----------------------------------------------- | :------------------------------- |
| 数值           | `100` / `0.1` | 常量                                             | `0.15`                         |
| 物理量（role） | 标识符            | 跨设备聚合的物理量，见[2.3](#23-物理量词汇表role) | `electric_output`              |
| 求和           | `sum(expr)`     | 对匹配设备求和                                   | `sum(capacity * unit)`         |
| 相除           | `div(a, b)`     | 比率表达式，分母含变量时**自动线性化**     | `div(Σcurtailment, Σoutput)` |
| 作用域         | `expr @ 范围`   | 限定物理量归属的设备类别                         | `capacity @ 光伏`              |
| 算术运算       | `+ - * / ( )`   | 四则运算                                         | `(a + b) * c`                  |
| 隐式乘法       | 相邻标识符        | `capacity unit` 等价 `capacity * unit`       | —                               |

**优先级**：`* / @` 高于 `+ -`，同级左结合。`@` 作用于其左侧整个表达式：`capacity * unit @ 光伏` 即 `(capacity * unit) @ 光伏`。

#### 2.2.3 作用域（@ 范围）

| 写法类型                   | 示例                                         | 说明                                   |
| :------------------------- | :------------------------------------------- | :------------------------------------- |
| **语义别名**（推荐） | `@ renewable` / `@ storage` / `@ grid` | 新能源（光伏+风机）/ 储能类 / 外部电源 |
| 英文类型键                 | `@ photovoltaic`、`@ wind_turbine`       | 与元件库注册键一致                     |
| 中文类型名                 | `@ 光伏`、`@ 风电`                       | 与界面元件名一致                       |

> 每个物理量都应携带自己的作用域；不带作用域的裸物理量在自定义约束中会被拦截报错。

#### 2.2.4 常用约束示例速查

| 工程需求               | DSL 表达式                                                                                | 界限     |
| :--------------------- | :---------------------------------------------------------------------------------------- | :------- |
| 光伏总装机不超过 20 MW | `sum(capacity * unit) @ 光伏`                                                           | ≤ 20000 |
| 风电弃电量受控         | `sum(electric_curtailment) @ 风电`                                                      | ≤ 限值  |
| 新能源台数不少于 5 台  | `sum(unit) @ renewable`                                                                 | ≥ 5     |
| 储能总装机上限         | `sum(capacity * unit) @ storage`                                                        | ≤ 限值  |
| 购电量受合同约束       | `sum(electric_input) @ grid`                                                            | ≤ 限值  |
| 自消纳率（占发电量比） | `div(Σ(output - input @ grid), Σ(output + curtailment)) @ renewable`                  | ≥ 限值  |
| 占用电比（占总负荷比） | `div(Σ(output - input @ grid) @ renewable, Σ(electric_input) @ 负荷)`                 | ≥ 限值  |
| 弃电率                 | `div(Σ(electric_curtailment), Σ(electric_output + electric_curtailment)) @ renewable` | ≤ 限值  |

> 提示：自定义 DSL 更多用于装机规模、购电量等**模板未覆盖**的约束。

### 2.3 物理量词汇表（role）

自定义约束中可引用的物理量共 **26 个**：

#### 非流量物理量（规划类）

| role         | 含义     | 典型用法                                      |
| :----------- | :------- | :-------------------------------------------- |
| `unit`     | 设备台数 | `sum(unit) @ renewable` 新能源总台数        |
| `capacity` | 单机容量 | `sum(capacity * unit) @ storage` 储能总装机 |

#### 流量物理量（8 类载体 × 3 种方向 = 24 个）

命名规则：`载体_方向`。方向：`input`（输入/购入/下网）、`output`（输出/出力/上网）、`curtailment`（弃能）。

| 载体前缀            | input         | output      | curtailment |
| :------------------ | :------------ | :---------- | :---------- |
| `electric_`（电） | 购电量/下网量 | 出力/上网量 | 弃电量      |
| `heat_`（热）     | 热输入        | 热输出      | 弃热        |
| `cool_`（冷）     | 冷输入        | 冷输出      | 弃冷        |
| `hydrogen_`（氢） | 氢输入        | 氢输出      | 弃氢        |
| 其余载体            | 同规则        | 同规则      | 同规则      |

### 2.4 软约束与松弛机制

系统级约束默认以**软约束**实现，避免个别约束过紧导致整个模型无解：

- 每条约束可独立选择是否软约束（`slack` 开关）；
- 软约束允许被轻微违反，违反量（松弛变量） 计入目标函数惩罚——**付出代价但保证有解**；
- 求解结束后，若某约束存在松弛，平台会在结果中**告警提示**，说明该约束实际未满足，需要放宽限值或核查输入数据。

**直观理解**：软约束像"带罚则的承诺"——优化尽量做到，实在做不到就"交罚款"并如实记录。硬约束则是"一票否决"，做不到整个求解直接失败。工程上先用软约束探明系统"能做到什么程度"，再决定是否收紧。

> **使用建议**：合规类约束（绿电占比、上网比例）保持软约束开启，先求解看结果再决定是否收紧为硬约束；装机规模类约束（储能/新能源总装机）一般为硬约束。

> ⚠️ **软约束的"买通"风险**：软约束能被违反，是因为违反要交的罚款**低于**为满足约束而多花的投资。当优化算下来"交罚款更划算"时，它会**主动选择违约**。因此求解成功 ≠ 约束被满足。
>
> **判定方法**：不要只看报告写了这条约束，要直接核对结果指标的实际值（如自消纳率实际 52% 而非要求的 65%）。
>
> **例外**：保供约束默认不松弛，其惩罚用的是**电不平衡惩罚价**（默认 10000 元/kW）——保供违约代价极高，不允许被轻易买通。

### 2.5 比率守恒：上网 + 自消纳 + 弃电 == 1

新能源发出的电，去向只有三类：**上网（g）、自消纳（s）、弃掉（c）**。平台强制三者满足守恒关系：

$$
g + s + c = 1
$$

优先级为 **上网 > 自消纳 > 弃电**。由此产生两条必须知道的行为：

1. **弃电率上限由引擎推导，不完全等同于您填的值**：按 `c = 1 − g − s` 计算。例如外部电源 最大上网率 20%、自消纳率下限 60% → 弃电率上限被推导为 20%。此时您手动填的"弃电率上限 50%"会被**下调并告警**；若您没有配置弃电率，引擎也会按此式**自动注入**一条弃电率约束。
2. **收紧一项必然挤占另一项**：把上网率压到 5%、又要求自消纳 ≥ 90%，弃电空间只剩 5%。新能源出力波动一旦超出该余量，就会触发弃电惩罚或约束松弛。

| 角色  | 参数         | 来源                                                              |
| :---- | :----------- | :---------------------------------------------------------------- |
| `g` | 最大上网率   | 外部电源组件属性（拓扑里设，守恒最高优先级）                      |
| `s` | 最低自消纳率 | 计算方案『最低自消纳率』字段（`MinGenerationSelfUse`）；或 `generationselfuse_ratio` 预设模板——**两者同时存在时以模板为准** |
| `c` | 最大弃电率   | `curtailment_ratio` 模板上限，**或由引擎按 1−g−s 推导** |

### 2.6 参数"设了却不生效"的退化规则

以下情况引擎会**直接跳过约束构建，全程无报错**。排查"参数明明填了却没作用"的问题时请对照此表：

| 约束类型                     | 不生效的条件                                                     | 正确做法                        |
| :--------------------------- | :--------------------------------------------------------------- | :------------------------------ |
| 下限类（自消纳率、占用电比） | 下限 ≤ 0                                                        | 需要生效就填大于 0 的值         |
| 上限类（弃电率、上网率）     | 上限 ≥ 100%（视为"不限"）**或** 上限 ≤ 0（视为"不允许"） | 需要生效就填 0~100 之间的值     |
| **上网率约束**         | 外部电源设为不允许上网                                           | 允许上网并填 0~100 之间的百分数 |
| **保供约束**           | 保供时长 0                                                       | 需要就填大于 0 的小时数        |
| **自定义表达式约束**   | 求解模式为两阶段                                                 | 模板预设（`UserDefineConstraint=1`）**支持**分阶段；**自定义表达式（=2）**与分阶段互斥，请改用统一模型 |
| **最低自消纳率**（`MinGenerationSelfUse`） | 填 0 或留空                                        | 需要生效就填 >0 的百分数（如 65）；与 `generationselfuse_ratio` 模板同时存在时以模板为准 |
| **`SystemConstraints` 内全部条目**（含预设类） | `UserDefineConstraint = 0`（不支持自定义）时整张列表被忽略 | 需要预设/自定义约束生效，请置 `UserDefineConstraint` 为 1（预设）或 2（自定义表达式） |

### 2.7 使用限制

| 限制           | 说明                                                                                 |
| :------------- | :----------------------------------------------------------------------------------- |
| 与求解模式互斥 | **自定义表达式约束（`UserDefineConstraint=2`）**与两阶段互斥，须用**统一模型**；**模板预设（=1）支持分阶段**（Phase 1 跳过比率类、Phase 2 生效） |
| 比率约束的分母 | 分母含运行变量时自动线性化处理，无需用户操心                                         |
| 物理量词表     | 只能引用词表内的物理量，未定义的标识符会报语法错误                                   |

## 三、报表计算原理

优化完成后，可在**财务评估模块**中对方案进行全生命周期的财务评价。平台共生成 **11 张财务报表**和 **1 张概览表**，其数据流动与勾稽关系、每一张报表的编制目的与核心计算方法如下。构成报表的财务参数见[第四部分](#四财务参数说明)。

### 3.1 报表体系总览与勾稽关系

平台共生成 11 张财务报表和 1 张概览表。其数据流动关系如下：

```
                            ┌─ 营业收入税金表(10) ─┐
 优化方案结果(systemData) ──┤─ 折旧摊销表(6) ──────┼──► 流动资金表(5)
 (收入/支出/投资)          │─ 投资使用计划表(4) ─┤       │
                            └─ 借款还本付息表(11) ─┘       │
                                 │                        │
     ┌──────────────────────────┼────────────────────────┘
     ▼                          ▼
  总成本费用表(7) ─────┐        │
     │                 │        │
     ▼                 ▼        ▼
  利润与利润分配表(1) ◄──────────┘ (总成本、税金输入)
     │
     ├───────────────► 项目总投资现金流量表(8)（融资前）
     ├───────────────► 项目资本金现金流量表(9)（融资后）
     ├───────────────► 财务计划现金流量表(3)
     └───────────────► 资产负债表(2)（平衡校验）
                              │
                              ▼
                          概览表(经济性指标)
```

**核心枢纽**：利润与利润分配表（表1）是连接"经营"与"现金流"的枢纽——它承接营业收入、总成本费用、税金，产出所得税与净利润；净利润又通过现金流量表影响累计盈余资金，通过公积金/未分配利润影响资产负债表的所有者权益。

**核心勾稽关系**：财务报表之间通过以下恒等式互相校验，任一环断裂都会导致后续数字错误。

**① 利润表勾稽链（表1）**

```
产品销售收入 − 销售税金及附加 − 总成本费用 = 利润总额
利润总额 − 弥补以前年度亏损 = 应纳税所得额（取非负）
应纳税所得额 × 企业所得税税率 = 所得税
利润总额 − 弥补亏损 − 所得税 = 净利润
净利润 − 法定公积金 − 任意公积金 − 投资方利润分配 = 未分配利润
```

**② 现金流勾稽链（表8/9/3）**

```
现金流入 − 现金流出 = 净现金流量
本年累计净现金流量 = 上年累计净现金流量 + 本年净现金流量
```

财务计划现金流量表的"累计盈余资金"即逐年累计的净现金流量，它同时作为资产负债表"流动资产"中的一项。

**③ 资产负债恒等式（表2）**

```
资产 = 负债 + 所有者权益
（流动资产 + 在建工程 + 固定资产净值 + 无形资产净值）
= （流动负债 + 建设投资借款）
+ （资本金累计 + 累计盈余公积 + 累计未分配利润）
```

平台在生成资产负债表时会逐年自动校验该等式，若不平衡会输出警告，提示检查上游报表。

**④ 成本勾稽（表6/7）**

```
经营成本 = 总成本费用 − 折旧费 − 摊销费 − 财务费用（利息支出）
```

折旧与摊销计入总成本费用，但**不产生现金流出**（钱在投资时已经花掉），因此在现金流量表中计算现金流出时用的是剔除折旧摊销后的"经营成本"。这是成本与现金流最容易被混淆的勾稽点。

**⑤ 投资勾稽（表4）**

```
项目总投资 = 建设投资 + 建设期利息 + 流动资金
资金筹措 = 项目资本金 + 债务资金（长期借款 + 流动资金借款）
项目总投资 = 资金筹措（两边必须相等）
```

**⑥ 所得税口径勾稽（表1/8）**

- 利润表中的"所得税"= 应纳税所得额 × 税率（按当年实际盈利计算）；
- 项目投资现金流量表中的"调整所得税"= 息税前利润 × 税率（融资前分析简化口径，只取非负）。
  两者口径不同，不能互相替代，属正常差异。

### 3.2 各报表计算原理

下面逐张说明每张报表的**编制目的**与**核心计算方法**。报表在界面上以"项目-子项"树形结构展示，每个子项对应一列逐年数据，年份从项目建设期第一年至运营期最后一年。

#### 3.2.1 营业收入、税金、附加和增值税估算表（表10）

**编制目的**：估算项目投产后各类能源销售形成的收入，以及按增值税核算规则产生的各项税费，是利润表和现金流量表的税金数据来源。

**核心计算**：

```
营业收入 = 售电收入 + 售冷收入 + 售热收入 + 售氢收入
   （均来自优化运行结果中的年收入，建设期内为 0）

销项税额 = 售电收入×电税/(1+电税) + 售冷收入×冷税/(1+冷税)
         + 售热收入×热税/(1+热税) + 售氢收入×氢税/(1+氢税)

进项税额 = 购电支出×电税/(1+电税) + 燃料支出×燃料税/(1+燃料税)
         + 材料费×材料税/(1+材料税)

应交增值税 = 销项税额 − 进项税额
城建税 = 增值税 × 城建税税率
教育费附加 = 增值税 × 教育费附加税率
地方教育费附加 = 增值税 × 地方教育附加税率
营业税金及附加 = 城建税 + 教育费附加 + 地方教育费附加
```

**原理说明**：增值税 = 销项 − 进项，即只对"增值部分"征税。所有收入/支出先做"价税分离"（除以 1+税率），分离出税额再计税。城建税及附加以实缴增值税为计税基数。

#### 3.2.2 资产折旧与摊销估算表（表6）

**编制目的**：把项目的大额一次性投资在运营期内逐年分摊进成本（折旧/摊销），并计算资产的净值变化。

**核心计算**：

```
实际年利率 = (1 + 名义年利率/计息次数)^计息次数 − 1
动态投资 = 静态投资(含利息的逐年建设投资) + 建设期利息
年折旧费 = 动态投资总额 × (1 − 残值率) × 固定资产比例 / 折旧年限
年摊销费 = 动态投资总额 × (1 − 固定资产比例) / 摊销年限
固定资产原值 = 上一年净值 + 当年动态投资 × 固定资产比例（逐年累计）
固定资产净值 = 原值 − 累计折旧
无形资产原值/净值 同上，比例为 (1 − 固定资产比例)
```

折旧与摊销仅在**运营期**且处于折旧/摊销年限内的年份计提，超过年限后归零。**建设期利息**计入固定资产原值（即"利息资本化"），体现为动态投资高于静态投资的部分。

#### 3.2.3 流动资金估算表（表5）

**编制目的**：估算维持正常经营所需的周转资金。采用"周转次数法"，即资金占用额 = 年某项现金流出 / 该项年周转次数。

**核心计算**：

```
经营成本 = 材料费 + 工资及福利费 + 修理费 + 其它费用 + 保险费（+ 燃料等）
应收账款 = 经营成本 / 应收账款年周转次数
存货     = (材料费+燃料费)/存货周转次 + (经营成本−保险费)/存货周转次 + 经营成本/存货周转次
现金     = (工资福利 + 修理费 + 折旧费 + 摊销费) / 现金年周转次数
流动资产 = 应收账款 + 存货 + 现金
应付账款 = (材料费 + 燃料动力费) / 应付账款年周转次数
流动负债 = 应付账款
流动资金 = 流动资产 − 流动负债
流动资金本年增加额 = 本年流动资金 − 上年流动资金
```

**原理说明**：周转次数越大，说明资金周转越快、需要的占用资金越少。流动资金在建设期末一次性投入，在运营期末全额回收，是现金流量表"回收流动资金"的来源。

#### 3.2.4 投资使用计划与资金筹措表（表4）

**编制目的**：明确"钱花在哪里"（项目总投资）和"钱从哪里来"（资金筹措），是融资方案的总纲。

**核心计算**：

```
静态投资总额 = 设备购置费 + 建筑工程费 + 安装工程费 + 其他费用
各年建设投资 = 静态投资总额 × 投资批次比例（比例自动校正，合计=100%）

实际年利率 = (1 + 名义利率/计息次数)^计息次数 − 1
各年长期借款需求 = 各年建设投资 × (1 − 资本金比例) + 当年建设期利息
建设期利息：分年计算，当年发生的借款按半年计息（系数0.5），
          用不动点迭代法反复计算直至收敛（利息计入本金后本金变，再算利息）

项目总投资 = 建设投资 + 建设期利息 + 流动资金
项目资本金 = 用于建设投资的资本金 + 用于流动资金的资本金
债务资金   = 长期借款 + 流动资金借款
资金筹措   = 项目资本金 + 债务资金   （必须与项目总投资相等）
```

**建设期利息的迭代原理**：建设期利息不是一次性算出来的——当年借款额包含当年的利息，而利息又依赖于含息本金。平台通过不动点迭代（反复代入直到利息变化小于阈值）求解这一循环关系，保证建设期各年"借款+利息"与"资本金+"投入严格吻合。

#### 3.2.5 借款还本付息计划表（表11）

**编制目的**：按还款方式和宽限期安排，逐年计算各类借款的还本、付息金额与期末余额。

**核心计算**：

**长期借款**（三种还款方式）：

```
等额本金：宽限期后每年还本 = 当年贷款额 / 贷款年限，逐年累计；
          付息 = 期初余额 × 实际利率 + 当年新增贷款/2 × 实际利率
等额本息：年还款额 A = P·r·(1+r)^n / [(1+r)^n − 1]（P为贷款本金总额，n为贷款年限）
          宽限期内只付息；宽限期后每年还本 = A − 当年利息
           （利息逐年减少，还本逐年增加，总额恒定）
到期一次还本：贷款到期年一次性偿还全部本金，每年只付息
```

**流动资金借款**：运营期每年付息 = 期初余额 × 利率，运营期末一次性还清本金。

**短期借款**（动态平衡）：当某年净利润为负时，企业需要借入短期借款弥补资金缺口；净利润为正时优先用于偿还短期借款。因付息会影响净利润、净利润又影响借款需求，平台用不动点迭代（循环求解直到净利变化小于阈值）得到收敛解。

```
期初借款余额合计 = 长期借款余额 + 流动资金借款余额 + 短期借款余额
当期还本付息合计 = 长期借款还本付息 + 流动资金借款还本付息 + 短期借款还本付息
```

#### 3.2.6 总成本费用估算表（表7）

**编制目的**：汇集项目运营期的全部成本费用，区分固定/可变成本，并计算现金流量表所用的"经营成本"。

**核心计算**：

```
生产成本 = 燃料及动力费 + 材料费 + 工资及福利费 + 折旧费 + 摊销费
         + 修理费 + 其它费用 + 保险费
财务费用 = 长期借款利息 + 流动资金借款利息 + 短期借款利息
总成本费用 = 生产成本 + 财务费用
固定成本 = 工资及福利费 + 折旧费 + 摊销费 + 其它费用 + 保险费 + 财务费用
可变成本 = 总成本费用 − 固定成本
经营成本 = 生产成本 − 折旧费 − 摊销费     （现金流量表的现金流出项）
```

**原理说明**：折旧和摊销是"非付现成本"——它们计入成本、冲减利润，但不对应当年的现金支出（钱在建设期已经花了），所以现金流量表必须用剔除折旧摊销后的"经营成本"作为现金流出。财务费用（贷款利息）在建设期结束后才发生，是成本中与融资结构直接相关的部分。

#### 3.2.7 利润与利润分配表（表1）

**编制目的**：按年度核算项目盈亏和利润分配，是所得税、公积金、未分配利润等一系列后续计算的总开关。

**核心计算**：

```
利润总额 = 产品销售收入 − 销售税金及附加 − 总成本费用
弥补以前年度亏损：历年累计亏损先用盈利冲销（先弥补后计税）
应纳税所得额 = max(利润总额 − 当年弥补亏损, 0)
所得税 = 应纳税所得额 × 企业所得税税率
净利润 = 利润总额 − 弥补亏损 − 所得税
法定公积金 = max(净利润, 0) × 法定公积金率（10%）
任意公积金 = max(净利润, 0) × 任意公积金率
投资方利润分配 = max(净利润 − 法定公积金 − 任意公积金, 0)
未分配利润 = 利润总额 − 所得税 − 净利润
息税前利润(EBIT) = 净利润 + 财务费用（利息）
EBITDA = 息税前利润 + 折旧费 + 摊销费
```

**原理说明**：亏损弥补采用"先亏先补、补足为止"的规则；亏损年不缴所得税、净利润为负；盈利年先用利润冲销历年亏损，剩余部分才计税。EBIT 与 EBITDA 剔除了融资结构和折旧摊销的影响，用于衡量项目"纯经营"盈利水平，是总投资收益率和调整所得税的基数。

#### 3.2.8 项目总投资现金流量表（表8，融资前分析）

**编制目的**：站在项目整体角度，不考虑融资方式（借钱与否），考察项目自身盈利能力。用于计算"项目投资内部收益率"。

**核心计算**：

```
现金流入 = 产品销售收入 + 回收固定资产余值(末年) + 回收流动资金(末年)
  其中 回收固定资产余值 = 运营期末固定资产净值
       回收流动资金   = 运营期末流动资金余额
现金流出 = 建设投资 + 流动资金 + 经营成本
         + 城建税 + 教育费附加 + 地方教育费附加
所得税前净现金流量 = 现金流入 − 现金流出
调整所得税 = max(息税前利润, 0) × 企业所得税税率
所得税后净现金流量 = 所得税前净现金流量 − 调整所得税
累计净现金流量 = 逐年累加
```

**注意**：该表现金流出**不含借款本金与利息**（融资前口径），因此现金流量只与投资和经营有关；所得税按"调整所得税"（息税前利润 × 税率）简化估算，而非利润表中的实际所得税。

#### 3.2.9 项目资本金现金流量表（表9，融资后分析）

**编制目的**：站在投资者的角度，只核算自有资金（资本金）的实际投入与回报，考虑还本付息，用于计算"资本金内部收益率（财务内部收益率 FIRR）"。

**核心计算**：

```
现金流入 = 产品销售收入 + 回收固定资产余值 + 回收自有流动资金 + 短期借款新增
现金流出 = 建设投资资本金 + 自有流动资金 + 经营成本
         + 长期借款还本 + 流动资金借款还本 + 短期借款还本
         + 长期借款付息 + 流动资金借款付息 + 短期借款付息
         + 城建税 + 教育费附加 + 地方教育费附加 + 所得税
净现金流量 = 现金流入 − 现金流出
累计净现金流量 = 逐年累加
```

**与表8的区别**：表9 多出"资本金投入、借款还本付息、实际所得税"项，去掉"债务性投入（全部建设投资改为资本金口径）"，因此其净现金流量反映投资者的实际现金收支。

#### 3.2.10 财务计划现金流量表（表3）

**编制目的**：从企业经营、投资、筹资三类活动汇总现金收支，判断项目各年资金是否充裕（累计盈余资金是否为正）。

**核心计算**：

```
经营活动现金流入 = 销售收入 + 回收流动资金
经营活动现金流出 = 经营成本 + 城建税 + 教育费附加 + 地方教育费附加 + 所得税
经营活动净现金流量 = 流入 − 流出

投资、筹资活动现金流入 = 项目资本金投入 + 建设投资借款 + 流动资金借款
                       + 短期借款新增 + 回收固定资产余值
投资、筹资活动现金流出 = 建设投资 + 流动资金 + 借款本金偿还 + 借款付息
投资、筹资活动净现金流量 = 流入 − 流出

净现金流量 = 经营活动净现金流量 + 投资筹资活动净现金流量 − 应交增值税
累计盈余资金 = 逐年累加净现金流量
```

**注意**：净现金流量在两类活动之和的基础上再扣除应交增值税（增值税作为价外税单独在现金层面流出）。累计盈余资金进入资产负债表"流动资产"。

#### 3.2.11 资产负债表（表2）

**编制目的**：反映项目在任意时点的财务状况，并验证整个财务模型是否平衡。

**核心计算**：

```
流动资产 = 应收账款 + 存货 + 现金 + 累计盈余资金
在建工程 = 建设投资 + 建设期利息
资产总额 = 流动资产 + 在建工程 + 固定资产净值 + 无形资产净值

流动负债 = 应付账款 + 流动资金借款 + 短期借款余额
非流动负债 = 建设投资借款（长期借款余额）
负债总额 = 流动负债 + 非流动负债

资本金 = 各年项目资本金投入的累计
累计盈余公积 = 各年法定公积金 + 任意公积金 的累计
累计未分配利润 = Σ(净利润 − 公积金 − 应付股利) 的累计
              （末年再扣减"长期借款还本 − 固定资产残值"差额，
                体现处置固定资产偿还借款的会计处理）
所有者权益 = 资本金 + 累计盈余公积 + 累计未分配利润

校验恒等式：资产总额 = 负债总额 + 所有者权益（逐年验证）
```

**原理说明**："在建工程 → 固定资产"的转化、折旧导致净值下降、盈利形成未分配利润、借款偿还减少负债，全部通过资产负债表逐年滚动体现。平台在生成该表时会逐年自动校验**资产 = 负债 + 所有者权益**，若偏差超过容差会输出警告，提示排查上游报表——这是检验整套财务模型勾稽正确性的最后一道关卡。

## 典型应用场景配置指南

### 绿电直连项目（688 号文合规）

#### 政策背景

根据国家发展改革委、国家能源局关于**绿电直连**的相关政策文件（发改能源〔2025〕650 号等，业界亦称"688 号文"口径），绿电直连项目的核心合规指标：

| 合规指标                       | 政策要求     | 平台对应配置                                                |
| :----------------------------- | :----------- | :---------------------------------------------------------- |
| **绿电占比（占用电比）** | ≥ 30%       | 预设约束`selfuse_ratio` 下限 30%                          |
| **上网比例**             | ≤ 20%       | 外部电源属性**最大上网率** = **20**（百分数口径） |
| **新能源消纳**           | 就地消纳优先 | 预设约束`generationselfuse_ratio` 下限（如 90%）          |

#### 配置步骤

**Step 1：项目设置**

| 参数         | 设置值                          | 说明                         |
| :----------- | :------------------------------ | :--------------------------- |
| 规划类型     | 绿电直连（或典型年 + 合规约束） | 激活绿电直连语义             |
| 求解模式     | 统一模型                        | 自定义约束仅支持统一模型求解 |
| 场景缩减类型 | 全周期聚类                      | 兼顾精度与效率               |

**Step 2：设置合规约束（自定义约束 → 选用模板）**

| 约束名称                 | 模板类型                    | 下限         | 上限        | 软约束 |
| :----------------------- | :-------------------------- | :----------- | :---------- | :----- |
| 绿电占用电比不低于 30%   | `selfuse_ratio`           | **30** | —          | 是     |
| 新能源自消纳率不低于 90% | `generationselfuse_ratio` | **90** | —          | 是     |
| 弃电率不超过 5%          | `curtailment_ratio`       | —           | **5** | 是     |

**Step 3：外部电源上网限制**

在外部电源组件属性中设置**最大上网率** = **20**（上网比例上限 20%），平台自动生成上网率约束。

> ⚠️ **百分数陷阱（高频错误）**：**最大上网率**按**百分数**解析，引擎内部会除以 100。**填 20 表示 20%；若误填为 0.2，实际含义是 0.2%**——上网通道几乎被完全堵死，新能源富余电无处可去，轻则大量弃电、出现"同时充放电"告警，重则模型无可行解。同类百分数口径参数还有：最低自消纳率、最大弃电率、峰谷差率、储能 SOC 上下限等。

**配套检查**：仅有上网率还不够，必须**同时**满足以下三项，上网通道才真正打通——
① **是否允许发电上网** = 允许；② **最大上网功率**（kW）> 0；③ **最大上网率** > 0。
此外还需在**数据模块绑定上网电价**（`psprice`），否则上网无收益，模型宁可弃电。详见[参数设置 · 上网电价绑定专题](../../50-topology-module/20-topology-modeling-workflow/20-setting-params/index.md#5-上网电价绑定专题)。

**Step 4（可选）：储能保供**

设置 `PowerGuarantee` = **4**（4 小时保供），滑动窗口法自动生成极端工况保供曲线，保障连续供电。

**Step 5：求解与合规校验**

求解完成后，在结果中检查：

1. 年度/月度**自发自用比例、上网比例、新能源消纳比例**统计是否达标（见[方案信息汇总](#2-方案信息汇总)）;
2. 是否存在**松弛告警**——有告警说明约束未满足，需放宽限值或调整容量；
3. 财务后评估的投资回收期与度电成本是否可接受。

> 平台支持一键生成**绿电直连可行性分析报告**，自动输出合规统计与越限标注——过去"先建后算、事后补数"，现在"以荷定源、源荷匹配"的合规性在规划阶段即被保证。

## 常见问题

是否支持以 IRR 最高为优化目标？

:   不支持，优化目标为综合成本，如需详细的财务评估，请选择财务后评估。

财务评价和方案优化的经济性目标测算有什么区别？

:   方案优化模块的经济性测算是相对比较粗略的，只考虑到了设备投资成本、设备年运维成本、购电以及购燃料等成本，并进行了简单的考虑项目生命周期的投资测算，而财务评价则是优化后评估，从更加全面的评价维度对整个项目进行了财务分析。通常进行到财务评价时，需要用户根据实际的设备建设规模对不同的优选方案设定不同的基础财务参数。

财务评估需要用户准备哪些输入？

:   两个层面：一是**方案结果**——由方案优化模块自动传入（设备投资费用、8760小时运行数据换算出的年收入/年支出/年运维费用），无需手动录入；二是**财务参数**——本文档"财务参数说明"中的六类参数，由用户按项目实际填写（建设期、资本金比例、利率、折旧摊销、成本费用、税率等）。建议先确认"建设投资明细"与"投资批次及比例"与项目实际资金安排一致。

为什么我改了资本金比例，报表里的净利润也变了？

:   这是正常的勾稽联动。资本金比例决定了借款规模，借款规模决定财务费用（利息），财务费用计入总成本费用，总成本费用直接影响利润总额与所得税。因此融资方案（表4）→ 借款还本付息（表11）→ 财务费用（表7）→ 利润（表1）是一条完整的传导链。这也是为什么"平均年总成本费用"这一概览指标会随融资结构变化的原因。

资产负债表提示"不平衡"警告是怎么回事？

:   平台在生成资产负债表时会逐年校验 `资产 = 负债 + 所有者权益`。若出现警告，通常意味着某一项来源数据异常，可以按以下顺序排查：① 确认"投资批次及比例"合计为 100%；② 检查折旧摊销表是否有年份超出折旧年限；③ 检查现金/流动资金估算是否出现负数；④ 检查累计未分配利润末年是否因还本调整出现负值。多数情况下是参数设置超出合理范围所致。

增值税为什么没有出现在利润表的成本里？

:   增值税是**价外税**，其税额已在销售/采购环节通过"价税分离"单独核算（表10的销项税额、进项税额），应纳税额只与"增值额"相关，不构成企业成本费用。因此利润表只包含以增值税为计算基数的城建税和教育费附加等"价内税费"，增值税本身在财务计划现金流量表层面从现金中扣除，避免重复计算。

内部收益率为 0 或显示异常，可能是什么原因？

:   内部收益率由牛顿迭代求解，当项目现金流符号多次反转（如后期又有大额资金投入）时，可能出现 IRR 不唯一或不收敛的情况，此时平台输出 0。建议先查看项目资本金现金流量表的"净现金流量"列，确认现金流是否呈现"先负后正"的常规形态；若运营期出现多年负现金流，需检查收入参数或建设投资分配是否存在问题。
